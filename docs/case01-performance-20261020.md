## 实际瓶颈

总耗时61.561分钟，需求提取/逐条生成/来源审核6.182分钟，评分55.378分钟。百炼72次评分接口响应合计52.209分钟（平均43.508秒，中位21.931秒，最长268.187秒），在当时单在途的调度下基本串行占据评分时间。评分墙钟与这些响应之差约3.17分钟，含限流间隔、调度/本地准备和阶段等待；旧账本没有时间戳，不能进一步精确拆分。

MaaS20次内容复核接口响应合计9.739分钟，但固定120秒开始间隔使其大量时间在等待。它在这轮主要与主评重叠，不能将两路响应时间相加后当作总耗时，也不能把61分钟全部归因于MaaS限流。

一例实际是两份候选、26页：7个需求、12条rubric、10次构建实际请求（含一次提取失败），以及20次内容主评、52次逐页视觉、20次独立内容复核，总计102次。92次judge都首次成功；重试并非主要瓶颈。沿用既有渲染，本轮没有LibreOffice重新转换。

原有调度有两层串行：A完成主评及复核后才启动B；每份文稿内部内容逐条串行、视觉逐页串行。`--workers`只并行case，所以一个case设置它不能解决问题。

## 已实现

- `candidate_workers`：候选并行；默认1保留原行为。
- `assessment_workers`：各评审者内部并行内容条目、并行视觉页面；默认1。每个视觉请求仍只一页一条，每个内容请求仍看完整稿。
- 每provider仍只有一个共享Client，统一控制实际在途数、启动间隔、预算、账本和熔断。候选数乘工作线程数不会突破provider信号量。
- 结果按原rubric顺序和页码排序；checkpoint由所属评审的收集线程写入，不由多个任务并发改写。PDF几何和局部渲染用锁串行，接口调用可并行。
- 请求账本新增准备耗时、信号量等待、启动间隔等待，以及开始/完成时间戳；历史账本不补造时间戳。
- 新增四份 `configs/contract-v25-*-fast.json`，以及可复用入口 `scripts/run_contract_v25_case01.py`。入口的输入记录编号分配有锁，避免并发覆盖请求记录。每阶段共用provider Client，初始化即采用一致的并发容量。

加速配置：judge/verifier在途数均2，candidate_workers与assessment_workers均2；百炼开始间隔保持20秒，MaaS独立内容复核间隔从120改为30秒。生成与审核模型、thinking、prompt、输出上限、权重、逐条粒度与全页覆盖均不变。MaaS30秒间隔是待在线验证的调度设置，不是已确认的服务配额；429仍遵守Retry-After、退避和熔断。

## 离线重放

读取实际每次响应时长，保持请求总量和单页两项顺序，模拟共享provider在途限制与启动间隔。阶段边界取历史保存文件的mtime；模拟不证明服务端并发能力。

| 调度 | 重放总耗时 |
|---|---:|
| 原串行设置 | 61.54分钟（实际61.56） |
| 只并行A/B，原间隔 | 46.79分钟 |
| 再并行条目/页面，原间隔 | 44.89分钟 |
| 加速配置，复核间隔30秒 | 39.02分钟 |

约缩短37%，只是基于本轮固定时长的估计；重放排队策略及未来响应波动/429会影响实测。并发主要减少等待，不承诺减少请求数、token或费用。未在线复测，不应称为已实测提速37%。机器数据与可重跑脚本见 `artifacts/performance-analysis-20261020/timing-analysis.json` 和 `analyze.py`。

## 下一次怎么执行

收到新的单例运行请求后使用新目录，默认加速配置：

```bash
.venv/bin/python scripts/run_contract_v25_case01.py \
  --out artifacts/<new-case01-run> --profile fast
```

`--profile standard`可恢复原调度。入口拒绝覆盖已有authorization；同provider预算跨生成/评分累计，失败重试也计数。固定操作上限百炼180、MaaS90不是长期或批量授权；本脚本只跑case01，不恢复任何旧余额。中断恢复必须先按唯一账本核算，不能换目录当作恢复来重置预算。

若用户只要求再次查看/生成报告，读取产物而不重调API；若只改judge且用户未要求全部从头，沿用仍通过来源/版本/哈希验证的rubric及渲染资产，只重新评分。不得将缓存旧答案称作新复测。当前入口的fresh运行仍重新构建rubric，不会隐式采用旧批准。

下一轮运行前说明预计调用量与耗时；完成后用新时间戳报告实际排队和接口耗时。本次484项全套离线测试通过，其中70项2.5与Provider专项；包含候选真实重叠、条目并行、全覆盖/顺序/输入隔离/结果一致、并发预算与账本检查。未进行新API调用。
