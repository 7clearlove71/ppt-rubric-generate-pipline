# 最后一轮修订：contract_v2 架构与实验预注册

日期：2026-10-14。本文件说明最终 `contract-v2.3` 架构、开发期修订与后续验证规则，不填写本轮最终分数、通过率、覆盖率或人工一致率。它不是把已经看过开发样例的过程追认为完全事前实验：旧开发集经验、v2.1 的 01 问题以及 v2.2 的来源独立抽查已经用于设计，v2.3 后续验证须按这里的规则解释。

目标是构建来源可追溯、适用于未来候选、判断和计分一致的 PPT rubric。人工偏好是外部参照，既不作为事实真值，也不作为寻找权重、平局阈值或判据措辞的优化目标。

## 历史过程提供的约束

此前从语义 rubric、来源归属审核发展到逐页证据账本和跨候选一致性复核，解决了部分工程问题，也引入了新的依赖与误差传播。最后一轮不是继续给相同链路追加解释，而是收缩生成与判定之间的可变接口。

| 历史经验 | 本轮设计回应 | 仍不能据此声称什么 |
|---|---|---|
| rubric 通过自动审核后仍可能重复检查同一事实；换一个 evidence ID 也能绕过精确去重。 | 来源要求先分类，程序强制映射到计分维度；每个来源要求只归一个专属条目；通用库显式排除专属条目负责的目标。 | 不声称结构唯一归属已证明所有自然语言判据语义不重叠。 |
| 候选帮助发现问题的同时，可能将某份作品的细节变成共同硬要求。 | rubric 构建和审核只接收来源，候选在 rubric 冻结后才进入评分。 | 不声称来源要求提取已经不需要语义审核。 |
| 事实原文、failure mode、judge prompt、覆盖映射分别生成会相互漂移。 | 只保留一个包含适用条件、通过条件与排除条件的规范条目，程序编译 judge prompt；source ID 由程序回填原文。 | 不把格式合法误当成通过条件合理。 |
| typed requirement 已限定归属，但自由 DESIGN 仍会在专属判据中添加相邻要求或新门槛。 | 删除自由 DESIGN 模型层；每个 Q 一对一确定性编译为一个 `R_<Q.id>`，独立审核直接核查来源提取本身。 | 不声称确定性编译自动保证 Q 的粒度、覆盖和语义互斥。 |
| 严格抄写来源导致标点、弯引号、不连续引用等非核心失败。 | 模型选择已提供的稳定来源 ID，不重新抄写来源原句；无效 ID 仍拒绝。 | 不静默删除错误来源引用后认定通过。 |
| 整篇判定与无原图复核能否定已经可见的局部遮挡，并最终互相同意错误答案。 | 视觉直接逐页判断，按固定规则聚合；不再用无图的跨候选一致性复核翻案。 | 不声称任何一次局部视觉判断都可靠。 |
| 逐字复制“约”等限定词的要求会把可接受的语境等价表达判错。 | 来源限定按语义、单位、时点与作用域检查，允许明确假设、正常近似及全篇适用声明。 | 不把假设自动当成正确推理，也不放过真的改变金额性质、对象或时间起点。 |
| 一致性复核需要模型对既有答案表态，容易受旧判断影响；多轮争议又产生大量 unknown。 | 两个内容评判独立读取同一任务、rubric 和单份作品，不互看答案；分歧直接保留区间。 | 不把模型共识视为真值，不为产出完整分数强行消除分歧。 |
| 小样本人工标签无同案重复标注，平局和固定分差不是同一个概念，视觉观看环境也可能不同。 | 保留历史标签，独立报告结构性可靠性、覆盖率、完整分数比较和区间比较。 | 不宣称人工错误，也不因一致率数字变化宣称进步。 |

历史依据见 `docs/validation-results-20261013.md`、`docs/evidence-repair-20261012.md`、`docs/evidence-continuation-20261013.md`；人工侧的详细审计见 `docs/final-revision-human-audit.md`。

## 构建：先定义来源契约，再看作品

数据流固定为：

```text
prompt 与附件
    ↓ 程序建立 source_catalog
K3 thinking 提取 typed requirements
    ↓ 程序校验来源引用、kind、唯一 ID
每个 Q 确定性编译为 R_<Q.id>（无 DESIGN 模型调用）
    ↓ 程序校验编译结果，附加固定质量库，编译判据和分数
MaaS Kimi-K2.6 thinking 独立来源审核
    ├─ 有可修的成立反例 → 仅修订 requirements → 再编译、再审核
    ├─ 仅固定库本身有不可由 Q 修复的问题 → 停止并保留失败
    └─ 批准 → 冻结 rubric 与来源/配置/协议指纹
                        ↓
                 才可开始读取候选评分
```

生成和来源审核均不接收候选 PPT、候选观察、模型身份、历史分数、人工胜负、人工理由或生成轨迹。每题只有一套 rubric，对当前及未来候选共同适用。冻结后的候选表现不能反过来增加判据、改权重或改变通过条件。开发期间发现通用协议缺陷时，需要另记版本修订并保留旧产物，不能暗中原位修改已批准条目。

每个来源要求有一个 `kind`。维度归属由程序强制检查，模型不能任意把事实分配给“完整性”后再在“正确性”重新检查。

| 来源 kind | 强制 dimension | 负责对象 |
|---|---|---|
| `fact` | `correctness` | 给定关键事实、数值、单位、对象和时间范围的存在且准确 |
| `deliverable` | `fulfillment` | 明确要求的其他独立模块、分析、计划等实质交付 |
| `presentation` | `narrative` | 来源明确的受众、用途、文体、时长和表达要求 |
| `information_boundary` | `integrity` | 来源明确要求的披露、核实或信息边界 |

每个 requirement 恰好确定性生成一个 `R_<Q.id>`；没有下游模型合并、扩写或另造专属条目。原 Q 的 `kind` 决定维度，`importance` 原样进入维度内权重分配，`source_ids` 原样保留。不同目标可以引用同一来源片段，因此不能把“source ID 相同”当成重复评分的充分条件。来源事实与其不确定性/单位/时间是同一目标；“近三年进展”不能被提取为必须逐字显示“近三年”，“20 分钟”也不能被变成必须写时长的排版要求。

模型只提取 `task_summary`、`source_policy` 和 requirements 中的 `id`、`kind`、`text`、`source_ids`、`importance`。`objective`、`scope`、`applicability`、`pass_condition`、`exclusions`、证据类型及作用域由程序模板确定；其中通过条件只由类型模板前缀和原 Q 文本连接，不能额外加入相邻要求。程序再唯一编译 `judge_prompt`，不接受另一份 `failure_modes`、`fail_condition` 或模型给出的 `score`。校验要求条目与 `compile_requirements(requirements)` 完全相等；仅有结构合法而被改写的条目也不接受。

“我会检查”“内容站得住”等一般提醒保留在任务摘要或来源政策，不独立变为扣分目标；真实受众、文体和时长要求仍保留。事实间的独立时序/衔接关系只检查已呈现组件的关系，缺失组件由其 fact 条目负责。真正独立模块、分析或计划本身缺失，仍不满足相应交付要求，不能用关系例外豁免。发布时记录来源、目录、请求配置、编译模板、来源修订指令与审核提示的指纹及 rubric 哈希；评分和导出前重新校验。

来源 ID 解决引用接口稳定性，不证明模型选择了正确片段或正确理解了它。`kind` 也是模型提取的语义结果；程序能检查映射，却无法仅靠类型系统证明最初分类或要求拆分合理。这仍由独立来源审核及开发抽查覆盖。

## 固定库与计分所有权

本轮维度预算沿用 **需求落实 30、正确性 25、信息诚信 15、叙事表达 15、视觉 15**。模型根据来源给出 1/2/3 的重要性，程序在固定维度预算内分配分数。拆条不能增加维度总额，但仍会改变维度内的相对分配，因此拆分是否合理仍是审核对象。

固定非视觉库只有三个通用目标：

- `C_REASON`：来源之外补充信息与计算、比较、推论是否成立；不再次处罚专属事实条目负责的来源事实缺失/改写，也不把单纯新增事实来源缺失当成推理错误。
- `I_BOUNDARY`：新增具体断言是否冒充已经证实的事实；允许合理建议和适用全篇的明确情景说明，不重罚专属披露目标、源事实改写或纯计算错误。
- `N_FLOW`：排除内容缺失、事实错误和遮挡后，仍独立存在的组织与衔接问题；不重罚专属受众、时长、文体和结构要求。

固定视觉库有两个目标：

| ID | 分值 | 判断范围 | 不重复处罚的范围 |
|---|---:|---|---|
| `V_READ` | 10 | 信息文字、数字、类别/轴/图例/单位实际可读；遮挡、裁切、缺失标签、NaN 等破损是否造成信息损失 | 几何框相交但笔画未重叠、无信息损失的装饰叠放、个人字号偏好 |
| `V_LAYOUT` | 5 | 在内容可读前提下，主次、对应关系、阅读顺序和视觉编码能否支持理解 | 不再处罚同一遮挡、裁切、对比不足、标签缺失；不强制模板、配色和图表数量 |

`V_READ:V_LAYOUT=2:1` 已写入本轮初始 `design-freeze.json`，v2.2、v2.3 均沿用这一分配。理由是让可读性有单一计分归属，同时保留独立的组织目标；不是看到本轮分数或人工匹配结果后调整视觉权重。五维预算也不为某个案例或某个候选修改。

这些仍然是二元 rubric：完全满足获得本条全部权重，有实质缺陷为零分，不能核验为 unknown。程序按整份 PPT 的条目权重计分，页数不是分数乘数。

## 审核角色与有限修订

当前来源提取配置为 `configs/contract-v2-k3.json`：百炼 `kimi-k3`，`enable_thinking=true`。独立来源审核使用 `configs/contract-v2-auditor.json`：MaaS `kimi-k2.6`，最终 v2.3 配置的 `thinking.type=enabled`；此前 v2.2 的该审核配置为 disabled，不能把这项变化隐去。审核输入是原来源、typed requirements、确定性编译后的 rubric 和固定库，不是作品分数。内容评分所用的 `contract-v2-verifier.json` 是另一个角色配置，仍为 `thinking.type=disabled`。

审核必须直接将 Q 文本与 source_catalog 原文核对，不能把提取出的 Q 当成权威。用最小成立反例检查来源覆盖、额外义务、通过条件与例外是否冲突、单一事实是否重复计罚，以及正常舍入/等价表达/明确假设是否被误拒。重复扣分反例须证明同一原子缺陷使至少两条都判 no；一条 yes、一条 no 不算重复，既有排除条件也不能被忽略。原文漏项允许 `item_ids=[]`，但必须引用真实 `source_ids`。无成立反例时批准；不能用“可能误读”增加无来源页数、位置或重复披露门槛。

`max_revisions=2` 的程序含义是：初始提取/编译/审核后最多再修订 requirements 两轮，共最多三轮提取/审核。每轮仅两次逻辑模型调用：一次 K3 提取或修订、一次 MaaS 审核；编译不调用模型，正常路径为每例 **2—6 次逻辑调用**。前置校验或请求失败可更早终止。审核拒绝只能改 requirements 的分类、原要求文本、来源引用或重要性，不能改原始来源、模型评分答案、固定库或添加候选相关要求。若某个问题只引用固定库条目、不能通过修订 Q 解决，程序立即停止；不能假装重新提取来源就修好了固定库。

每轮保存 `requirements-<revision>.json`、对应编译产物与审核记录，达到修订上限仍失败则如实保留。每个逻辑请求最多三次实际尝试，HTTP 重试另计；传输或输出校验失败不被改写为成功。本轮用户解除请求数限制，但没有把协议改成无限语义修订。

`design-freeze.json` 保留初始权重及版本修订依据；早期 `max2 source-only audits per case` 的严格执行含义是“初始审核加最多两轮修订审核”，不是总共两次审核。最终 v2.3 的来源编译路径、审核 thinking 设置和指纹须结合当前源码/配置冻结哈希及每份 rubric provenance 读取，不能用一份 v2.1/v2.2 批准记录冒充 v2.3 批准。

## 评分：独立内容评判与局部视觉聚合

每次请求只包含一份匿名候选。文档 ID 由文件内容哈希生成，页 ID 属于该文档；它们不表示质量或来源模型。模型不接收其他候选、候选 A/B 身份、分数或人工标签。

**内容评判。** 百炼 K3（`contract-v2-judge.json`，`enable_thinking=true`）为主评；MaaS Kimi-K2.6（`contract-v2-verifier.json`，`thinking.type=disabled`）以相同来源和同一 rubric 独立评判内容条目。两者都查看这份作品的全部原始页面，并可用提取文字辅助；后者不接收前者答案、理由、缺陷或检查点。可并行调用不等于统计独立，独立的是输入隔离与判定过程。来源审核启用 thinking 不代表内容 verifier 也已更改。

内容 no 需要指出明确页码和实际缺陷；声称全篇缺失时需显式声明已检索全部页面。yes 也需给出支持页面。来源引用仅选择已有 ID，由程序回填原文。条目覆盖、页码、合法 ID、缺陷对象等校验是结构检查，不替代语义真实性判断。

**视觉评判。** K3 每批最多查看三张原页，附带同页真实局部放大图；当前实现每批最多追加三张局部图，并受执行 provider 的图片容量限制。每页分别对两项视觉标准输出 yes/no/unknown。文字框几何信息只用于定位裁剪，不自动判定笔画重叠；不转发旧 ledger 观察或其他候选的几何信息。

每个视觉条目的整篇聚合固定为：

```text
任意页面 no → 本条 no
否则，任意页面 unknown 或没有页面观察 → 本条 unknown
否则，全部页面 yes → 本条 yes
```

局部确认的 no 不会因为其他页通过或未知而变成 yes。整篇仅损失本条一次权重，不按坏页数或裁剪数重复扣分。遮挡由 `V_READ` 负责，不能换成“层级混乱”再让 `V_LAYOUT` 失败。后续不设置无图的跨候选复核环节，也不让另一个答案促使模型改判。

no 同时给出按文档、页码和实际对象命名的缺陷 key，不能包含 rubric ID。程序发现同一 key 被多条目使用时，保留原判并将涉及条目记为归属未决；不擅自决定某条扣分、某条恢复。不同 key 下的语义重复无法保证被检出，这是已知限制。

**分歧处理。** 经双模型评判的内容条目，只有双方均 yes 或均 no 才形成对应合并判定；yes/no 分歧、任何一方 unknown 或调用不可用均保留 unknown。双方都 unknown 也不是共识通过。没有投票、没有按照人工偏好裁决、没有将主评答案默认为正确。

本轮 `verification_content_only=true`，视觉只有 K3 单评。视觉条目明确标记 `not_independently_verified`，不称为独立共识。主评完整分数与合并分数分开保存；任何正权重未决时，合并完整总分为 null，并提供上下界。

## v2.1 → v2.2 → v2.3 的开发期修订记录

v2.1 的 01 初始 rubric 曾获自动 approve。随后独立的本地语义 QA 发现：关键事实 `R01/R02/R03` 被分到 fulfillment，通用 correctness `R09` 又检查一次；`Q08` 还把时间范围变成必须字面标注的义务。这说明 source-only 输入本身不足以防止重复判据，自动批准也不是质量终点。

原产物、审核、状态、请求快照和语义 QA 已保留在 `artifacts/final-revision-20261014/pre-typed-contract/`。该批准不作为最终输出。修订到 `2026-10-14.contract-v2.2`、rubric validator 2 后，增加 typed requirement 到 dimension 的强制映射、程序固定通用质量库及其专属排除条件；同时明确用途/时间范围不能被转成字面标签要求。该版仍有自由 DESIGN 模型层。

v2.2 的 01、02 自动审核也曾批准。随后仅依据来源、requirements、rubric 与审核记录的独立抽查，在 02 得到三个成立反例；该抽查没有查看候选、评分或人工标签，详见 `docs/contract-v23-source-only-audit.md`：

1. Q05 只要求农户人均月增收约 1800 元，DESIGN 生成的 R03 却补入“按件计酬”；R06 又已独立要求“农户在家编织按件计酬”。只删“按件计酬”、保留收入等其他内容，会让两条同时失败。这是实际判据的重复，不是假设两份真实作品应有何排名。
2. 来源只说会检查“标题、图表位置”，Q15 没有每页标题要求，R11 却新增“各页有标题”。一张逻辑连贯、信息清楚的整页图片或图表若未另设标题，会因新增实现门槛失败。
3. Q07—Q09 分别要求各年阶段事实，Q10 及对应关系判据又要求完整递进序列；删除第三年品牌/电商组件，会同时影响组件事实与完整序列。关系要求须限定为已呈现组件的时序/衔接，不能重罚组件缺失。这也说明仅去掉下游 DESIGN 不能自动消除上游 Q 的重叠。

最终修订到 `2026-10-14.contract-v2.3`、rubric validator 3：取消全部自由 DESIGN 模型调用，每 Q 一对一程序编译；审核和有限修订转向 requirements 自身。确定性类型模板保留等价表达与固定所有权排除条件，一般用途/检查提醒不再单列扣分目标，来源关系要求明确缺失组件归属。来源 auditor 同时从 disabled 改为 enabled thinking；主评仍 K3 thinking，内容 verifier 仍 K2.6 disabled thinking。

各版原始产物按内容哈希归档，不原地重标，旧尝试照常进入消费记录，历史快照不再重复计费。这是 v2.1、v2.2 开发问题触发的明确协议演变，不得表述为“同一版从头一次全部通过”。最终验证按 v2.3 冻结协议执行，质量失败原样保留，不继续语义改版直到得到期望排名。

## 验证范围与预定报告

开发范围固定为 01、02、03、05、06、09、10。04、07、08 为留出，用于任何后续独立验证前必须已冻结规则，并通过显式入口开放。本文不声称已经运行留出，也不读取或汇总留出标签。

以下检查在查看本轮最终比较结果前确定，不以通过率调整门槛：

1. **离线契约检查。** 验证来源目录与哈希、kind/维度映射、每 Q 一对一确定性编译、编译结果完全相等、唯一 judge prompt、固定维度预算、approved/provenance 绑定，以及导出和评分使用同一契约。有效等价表达与实际错误均需有正反例，不能只测 schema 是否接受。
2. **构建有效性。** 报告每例最终批准或失败及实际修订次数；独立语义 QA 与自动审核结果分别保存。失败不从分母删除，也不因收费额度允许就无限重试语义质量。
3. **四个固定视觉组件案例。** 使用 `local-ground-truth.json` 中已经实际查看的三处明确重叠与一处无重叠图像，以本轮冻结的视觉 prompt 做盲回归。预期答案、先前描述、来源 QA、候选身份和胜负不发给模型；只给中性标识和图像所需的固定判据/响应格式。结果必须同时看分类和实际对象关系，不能只看 no 恰好命中。
4. **单份作品全量评分。** 对批准 rubric 的候选完整提供全部页面，分别记录内容主评、内容独立评判、视觉逐页判定、合并判定、调用失败与条目未决权重。局部组件通过不替代全量评分。
5. **完整分数比较。** 仅在两候选合并分数均完整、配置和 rubric 相同且人工标签明确时计算严格匹配率；固定平局阈值仍为 3 分。报告明确人工标签数、完整可比数和未完成原因，不将 unknown 变成零分、平局或人工不匹配。
6. **区间比较。** 另行报告在所有未决项取值下仍成立的偏好。若 A、B 区间分别为 `[L_A,U_A]`、`[L_B,U_B]`，差区间为 `[L_A-U_B,U_A-L_B]`；其下界大于 3 为稳定 A，上界小于 -3 为稳定 B，整个区间位于 `[-3,3]` 才为稳定平局，否则未决。这不是完整分数一致率，不能混在同一分母。
7. **权重稳健性诊断。** 以固定原权重的每维 0.8/1.2 倍、再归一化至 100 的全部 32 个组合报告结论稳定性。只作敏感性描述，不挑一个更匹配人工的组合作最终权重，不据此改变原总分。
8. **人工标签可靠性。** 使用 comparison-only `label_reliability` 摘要：原来源、现有评测者记录数、平局/未定、盲法/独立性/复评与渲染证据。未记录的信息为 unknown，不能直接断言非盲评；不修改历史选择，不从理由推断未定标签。
9. **消费与失败。** 唯一活动账本跨命令累计所有实际请求与失败；来源/代码快照不重复累计。缺失 usage 不记零，价格未核实不估算金额。恢复仅复用同内容缓存；内容/协议变化必须留版本指纹。

不同层次的检查不能互相替代：网络成功不是结构成功，结构成功不是语义正确，模型同意不是事实正确，人工匹配也不是以上问题均已解决。最终报告应给出对任务有效性的证据与限制，不预设一致率必须提高。

## 已知局限与不作出的承诺

- **二元条目的饱和。** 泛型条目没有适用现象时会自然通过；许多条目全 yes 可以使分数接近满分，但不代表两份作品整体质量相同或接近完美。反过来，一处遮挡与多页系统性遮挡在 `V_READ` 中均损失一次 10 分，区分不了范围与修复成本。逐页记录可展示范围，但本轮不临时改成按严重程度或页数加权。
- **泛型通过的识别力有限。** 固定通用库能建立底线，却不保证捕获某领域最关键的技术错误。事实数量、requirements 拆分和重要性还会改变维度内分数分配；它们未由 typed mapping 自动解决。
- **模型家族相关性。** K3 与 K2.6 都属于 Kimi 系列；不同供应商端点及独立请求不保证训练、先验或错误独立。双方同意仅是额外佐证，不是无偏裁决或统计独立的重复测量。
- **视觉为单评。** 正式视觉判定只由 K3 完成。四个局部基准来自已知开发缺陷与明确负例，不能估计广泛视觉准确率、召回率、校准度或其他渲染器上的质量。它们由本地代理实际看图建立，不是新增独立人类复评；组件通过也不能证明整套视觉链路没有漏检。
- **局部图选择有限。** 所有原页都提供，但额外放大图受数量、几何启发与图像容量限制。未被选为放大图不等于没有缺陷；bbox 相交也不等于存在缺陷。整页阅读仍有分辨率和注意力限制。
- **来源分类仍有语义风险。** `kind`、独立目标、必要程度、事实与建议边界都由模型解释；错误分类可在结构完全合法时通过。固定预算要求存在独立交付条目，若未来来源不支持，应暴露不适用/失败，不能为凑维度编造要求。
- **语义重复无法全靠 key 排除。** 同一损害用不同对象名或不同 key 表达时，程序可能漏检；固定库排除条件是约束，仍依赖模型正确执行。
- **分歧区间可能较宽。** 把真实分歧保留下来会降低完整评分覆盖率；这比虚构完整分数更诚实，但不是已经解决评分能力的证据。稳定区间偏好也只对当前条目与判定成立。
- **开发集外推有限。** 本轮使用了历次开发故障设计策略，人工本身也缺同案重复标注。开发匹配率、四例组件回归、模拟客户端测试均不能代替冻结后的新案例验证。旧版与本轮的覆盖、协议和模型不同，不把百分比变化解释为单一架构的因果收益。
