# contract-v2.4 授权开发验证（2026-10-19）

用户明确回复“批准”后启动本轮，目录为 `artifacts/validation-20261019-contract-v24/`。这是新授权，和[改进单例及旁路记录](improvement-validation-20261019.md)分开核账，不复用历史余额。

范围为开发01、02、03、05、06、09、10，14份PPT、130页；百炼K3最多729次、MaaS Kimi-K2.6最多561次实际请求，均含失败、重试和恢复。每逻辑调用最多3次尝试，来源最多2轮修订。不运行留出，不将人工偏好或诊断预期传入模型，不按排名反复重判。

## 门槛和执行顺序

先运行最短的独立视觉门槛：6个冻结图像样本，最多18次实际请求，计入百炼总额。全部预期项须匹配，12个视觉判断均不可为unknown或接口失败；另由Codex直接核对原图和响应中的对象、位置、信息损失、正常对照及扣分归属。该核查不是新增真人标注。任一门槛失败停止扩展，不用其他样例成功抵消。

视觉通过后才运行固定20个文本样例的同模型方法对照。新方法的K3与K2.6均须满足已冻结的正反例及对象/理由门槛，旧方法如实保留表现。随后逐例构建并严格验收7套来源rubric；全部通过后冻结，再对同图的14份作品完整评分。此前03单例没有获得有效批准，不能代替新轮来源验收。

唯一累计账本为本目录 `bailian-api/requests.json` 和 `maas-api/requests.json`。同provider使用一个共享Client限流；恢复须从当轮总额扣除所有已发请求，不能按命令重置。来源CLI会继续已排队用例，本轮不使用其队列来实现失败停止，而由调度器逐阶段放行。

## 启动检查

正式分工维持K3来源提取/主评/视觉、K2.6独立来源审核/内容复核。来源审核thinking开启，独立内容复核关闭；不使用GLM或Qwen替代。6张原图及4张局部图的哈希均与登记输入匹配。

视觉组件回归现同步启用正式评分的 `require_diagnostics` 输出校验。方法对照汇总只接受状态有效的答案；失败响应保留但不计为匹配。启动前完整离线测试428项通过，源码、配置和诊断集共35份文件冻结并保存哈希。

## 最终结果：视觉答案命中，理由门槛未过

本轮已关闭。6个预先指定的视觉判定全部匹配，12个逐条回答均为有效yes/no，无unknown、格式失败或重试。它们是已见开发样例的组件结果，不能称为总体准确率或新协议完整验收。

## 已停止的扩展及用量

依据预先声明的对象/理由门槛，停止后续20样本同模型文本对照、7例来源构建/审核和14份成品评分。不运行留出；没有新人工比较，明确人工标签覆盖0/6，一致率不可计算，不能记为0%。新版本未通过生产质量验收。

本轮仅使用百炼K3 **6/729次**实际请求，全部HTTP 200及结构有效，服务报告 **54,837 tokens**，无缺失usage；MaaS **0/561次**，没有其他模型调用。唯一两本账为 `bailian-api/requests.json` 和显式空账 `maas-api/requests.json`；不存在运行中worker或started请求。35份冻结源码/配置/诊断文件哈希全部匹配。

`authorization.json` 和共享预算已关闭，未用723次百炼、561次MaaS不滚存为后续授权；没有为消耗额度继续调用。结果、停止原因与账本哈希见 `validation-summary.json`、`execution-status.json`、`shared-budget.json` 和 `final-accounting.json`。本轮不追加语义重判，不以当前6个标签命中宣布内容、来源或完整评分已经恢复。

剩余问题是视觉模型仍会扩大“实际丢失的信息”。后续修订需要单独核验受影响文字行与仍可见的数值，保留真实遮挡依据和明确的损失边界；本轮没有据核查人工改写模型理由或继续调提示词。
