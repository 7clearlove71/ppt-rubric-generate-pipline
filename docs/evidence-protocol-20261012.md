# 证据优先评分协议（实验版）

现行实现与修复验证见 [回归修复及经验记录](evidence-repair-20261012.md)。本文保留下列 `.2` 协议设计与失败实验历史；其中自动改派算术缺陷、双边传播unknown及旧配置使用方式已被修正。

本轮根据用例03实测中的重复扣分、算术误判和候选间标准不一致，新增 `evidence_v1`。实现阶段通过93项离线测试，未调用外部API。随后按用户要求完成7个开发用例真实生成验证，0/7批准，人工一致率不可计算；详细记录见下方实测结果。历史分数、人工标签和留出集保持原状。

最新一次实测已改回K3生成/观察/审核：1/7批准，09进入评分但最终双方各9条unknown，仍无法计算人工一致率。下方同时保留MaaS生成版本与K3生成版本，不能将两个版本混为同一次实验。

## 本轮改变

| 已发现的问题 | 新机制 | 仍需验证的部分 |
| --- | --- | --- |
| NaN、文字重叠被多个条目重复扣分 | 评分前冻结 `failure_modes`，每类缺陷只归属一个条目；判定只能确认归属于自己的已登记证据 | 改写表述后的同一缺陷仍可能被模型登记两次 |
| 未提供日期在A中扣分、在B中放过 | 独立评分后逐条比较匿名候选证据和判定；最多重判一次并再次复核 | 复核模型可能共享原判定的偏差 |
| 错误接受计算和推论 | 证据保留数量、单位、分母、时间起点；Decimal复算，错误必须被明确处理；提示词要求定量解释需要核对的推论 | 操作数、单位及关系的提取仍依赖模型 |
| 逐页发现问题未被最终判定处理 | 每个潜在缺陷必须 confirm/reject/uncertain，不能跳过 | 模型仍可能漏看缺陷或给出错误反驳 |
| 失败后残留旧完整分数 | 开始评分前归档旧结果；缺证据或一致性未解决时保留unknown | 严格拒绝可能降低完整评分覆盖率 |

权重仍为30/25/15/15/15，一个题目仍只有一套rubric。不向生成器、judge或一致性复核器传递人工标签、真实模型身份、轨迹或总分；不调权重强行贴合人工胜负。现有分歧也不足以证明人工有偏，人工可靠性仍需独立复评和标注者间一致性数据。

## 数据与执行

1. 生成或复审rubric时增加 `failure_modes`，每项含 `id / owner / definition / exclusions`。每条rubric必须拥有缺陷类型；视觉可读性、图表标签、视觉层级及推论有效性必须定义。边界文字须原样写入所属 `judge_prompt`，确保导出后仍可见。结构校验和语义审核共同检查，结构通过不是语义互斥证明。
2. 每页一次图像请求，登记 `quote / location / statement / kind / failure_mode / source_refs / quantities / calculations`。kind区分事实、推论、假设、建议和视觉现象；来源引用须匹配原文。程序赋予 `p1_e1` 等证据ID。同页相同位置及引文的缺陷记录不能重复登记。
3. 程序复算加减乘除及“相对基准超出比例”。例如当前值比基准高29%，超出量为 `current × 29 / 129`。reported按其小数精度核对。计算不符仅登记为潜在推论缺陷，不能直接当作扣分事实。
4. 每条独立judge接收来源、整份证据、图片及本条归属范围，返回 `answer / pages / evidence / evidence_ids / failure_ids / resolutions`。no必须有已确认且归属于自己的缺陷；拒绝程序算术标记也必须给出理由。新发现但未登记的证据不能临时编造ID，应返回unknown。
5. 每条进行一次跨候选文本复核，只给同一标准、匿名证据及判定。发现不一致，最多对涉及候选重判一次，再复核一次。不一致仍存在、复核失败或初判unknown，则该条所有候选均unknown；不强制相同答案，也不直接选择胜者。

输出包括 `<candidate>-evidence.json`、`<candidate>-initial.json`、`consistency.json` 和最终 `<candidate>.json`。历史完整结果归档为 `*-superseded-*.json`。unknown和未覆盖条目不作为零分、不从分母删除，不产生完整总分或胜负。

### 已核实的质量问题

1. **计算关系登记错误传递到评分。** 09/B第4页原图标注员工320→410、净增90、≈+28.1%，页脚明确写90÷320。90÷320×100=28.125%，28.1%是正确的一位小数近似。但证据提取使用了不适用的运算，产生约19.74的程序复算结果，初判R09据此声称作品计算错误。程序正确执行一条错误的计算关系，并不证明PPT错。A的相关算术证据也存在问题，初判为unknown；最终该条双方均unknown，原始误判仍保留。该例只证明其中一项算术批评错误，不等于整个推理条目应通过。
2. **可见重叠漏检。** 09/A第1页金色“亿”字与绿色“同比”明显重叠；逐页证据未将其标为可读性缺陷，初判R14又称“无叠印或裁切”。最终R14因重判未解决而为unknown，不把这个unknown解释为已正确识别重叠。
3. **一致性复核存在疑似过度拒绝。** R04双方重判均为yes，都论证标题先给结论、下方展开支撑，第二次复核仍称判定相反并拒绝。解释形式的差异被当作标准漂移，可能产生额外unknown；需要进一步验证复核器，而不是直接改最终判定。
4. **跨条目解释仍有矛盾。** A第4页无标签折线在初判R14被称为装饰线，在R16又被当作数据图扣分。同条标准的跨候选复核不能直接保证同一候选的跨条目解释一致。

这些抽查没有修改rubric、人工标签、模型答案或最终分数。图片及原始证据、初判引用位于 `case09-quality-findings.json`，生成诊断位于 `generation-diagnostics.json`。
