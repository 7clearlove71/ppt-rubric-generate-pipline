# Judge 合批实验（2026-10-23）

用户要求在准确度相近的前提下，尽量增加一次 judge 的 rubric 数量。实验工具为
`scripts/probe_judge_batch.py`，独立协议为 `judge_batch_probe_v1`，输出位于
`artifacts/judge-batch-probe-20261023/`。主 pipeline 仍使用原逐条判断协议。

## 固定范围

- 内容：开发案例02/A（qwen3.8-max来源目录，10页）与03/B（qwen3.8-max来源目录，8页），共54条。来源目录名不证明生成模型。
- 内容分组：3、5、10、整份全部条目（分别33、21）四种设置，保持原rubric顺序分组，每种覆盖相同的54条；末组不足批次大小时正常发送。
- 视觉：02/A第4、8页、03/A第4页、03/B第6页；分别以3、5条分组，共四页、每页五条。只合并同页rubric，不合并页面。
- 逐条复测：02/A的R_Q25、C_CONSISTENCY、C_COMPARE；03/B的R_Q10、C_REASON、I_BOUNDARY。使用原始单条system/payload/images/suffix，作为稀疏波动对照。
- 固定随机种子打散57个逻辑调用的执行顺序。共262个逐条判断；不以中间结果增删样本，不按结果重试。
- 不读人工标签，不运行留出案例，不恢复09，不改历史结果，不重开旧授权。

## 语义与输出

K3、thinking、输出上限、原始任务/来源、整稿图片/PDF文字、原页/局部图均沿用已有输入。
语义判据沿用原公共提示中的完全满足为yes、部分满足为no，材料不足才unknown。
批量版改为每个rubric独立输出ID、简短理由、yes/no/unknown的JSON数组；不提供历史答案、分数、人工偏好或候选名称。
因输出接口也发生变化，本实验比较的是整套批量接口与原单条接口，不能把差异全部归因于条目数量。

解析器严格拒绝重复JSON键、缺失/重复/额外ID、缺少理由、非法答案。不以总评补齐缺项。
实验单独存原文与解析结果，未将JSON改写为旧协议boxed，未迁移旧检查点。

## 判读与预设门槛

以逐条历史结果为一致性对照，不把它当真值，不报告“准确率”。重点同时检查：

1. 逐条一致率至少95%，原no保留至少90%；关注全yes占比掩盖漏检的风险。
2. 每份候选的内容分数变化不超过3分，无新增模型unknown或缺失ID。
3. 逐项阅读差异理由，并根据原图和来源辨别可能的改进、退化和争议。
4. 供应商响应耗时、tokens、失败/格式重试分别统计；本地排队时间与响应耗时分开。

这些是筛选门槛，不是统计等价性验证。样本只有两个内容候选和四个视觉页；条目共享同份PPT、同页，不能当作独立随机样本宣称泛化。
视觉页的权重不能相加当作整稿扣分，正式政策仍须先按页any-no聚合，权重只计一次。
历史响应时长不是同期随机对照，因此响应秒/条的变化也不能直接称为端到端提速。

## 执行与记录

本次操作上限90次实际API请求，由代理设定，包含失败与重试。一个共享Client，并发2、启动间隔20秒，保留原熔断与有界重试。
凭据优先读环境，缺失时只从既有凭据文件读入内存；不写回凭据。历史账本不计作本轮新增消费。
`api/requests.json`是本轮唯一请求账本，`cache`、`results`、`summary.json`不是额外消费。
原始输入与图片SHA、样本计划、范围授权分别保留在`plan.json`、`authorization.json`。

只准备/离线汇总（不调用模型）：

```bash
.venv/bin/python scripts/probe_judge_batch.py --out artifacts/judge-batch-probe-20261023
```

已获相应范围授权时，显式增加`--run`执行。关闭的实验授权不能自动重开。
不要把本目录的90次上限用于其他实验或理解为未来授权。

最终结果由该目录的`report.md`、`analysis.json`和`summary.json`提供；运行中的结果是部分结果。
