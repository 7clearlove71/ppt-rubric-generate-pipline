# contract-v2.5：轻量模式与全量模式

2026-10-23 当前流程支持**轻量模式 `light`（默认）**和**全量模式 `full`**。两者的区别仅为 rubric 审核：轻量模式跳过审核，首版 rubric 直接进入单 K3 judge；全量模式初审后最多修改两轮（最多三次审核），仍未通过也继续 judge，结果明确标记“审核未通过”并保存原因。审核接口/格式错误或修改失败时使用最近一版完整、通过程序校验的 rubric，保留错误记录；没有任何完整 rubric 时仍报告生成失败。

最新用户模板已逐字接入，审核输入为原始需求、来源、评分约定及全部条目的 `id/content/dimension/score`，按实际 `dimension` 核对预算，禁止按编号猜维度。严格 JSON 解析保持不变：只有合法 `{"issues":[]}` 代表审核通过，继续评分不等于审核通过。`source_audit.status` 分别为 `skipped/passed/not_passed`，模式、原因、原始问题与审核历史随 rubric、评分报告、汇总及导出一起保存。rubric validator **10**、judge validator **10**；历史产物不改写，旧批准不能直接迁入当前流程。五维30/25/10/15/20和single_k3不变；内容提示词保持逐条，视觉采用严格JSON合批提示词。本次只改代码并做离线验证，未调用付费API或重跑02。

2026-10-23 当前默认：`light` 轻量模式；批量任务并发 `--workers 10`；K3 judge 全局最多 30 个在途请求，条目/页面调度默认 30。内容仍为一条 rubric 一次调用，视觉改为同页全部 5 条一次调用，共用该页原图和局部放大图，严格按 rubric ID 返回独立理由及 `yes/no/unknown`。视觉请求数由 `5×P` 变为 `P`，每稿评分调用为 `C＋P`（无视觉项时为 `C`）；不含失败重试。逐页 any-no 聚合、五维30/25/10/15/20、每条权重只计一次及同题 unknown 共同剔除均保持。judge validator 升为10，rubric validator仍为10；旧检查点不能混入新协议，历史记录不迁移或重评。本次仅离线实现与验证，未新增付费API调用。

## 同题比较中的unknown共同剔除（2026-10-22）

同一任务的全部候选评完后，取最终rubric判断为unknown的条目并集；任一候选unknown，该条在全部候选计分时都忽略，包括其他候选该条的yes或no。模型材料不足、接口失败和格式校验失败产生的unknown均适用，保留各自原始证据与执行状态。视觉仍先按“任意页no，否则有unknown，否则全yes”聚合；只有最终该条unknown才触发共同剔除。

比较分数为剩余条目中yes的原始权重之和，比较满分为全部剩余权重之和，不重新分配或归一化。例如某条10分被剔除，所有候选共同在90分满分下比较。3分持平阈值继续按原分值尺度执行。没有unknown时分数与原算法相同；全部条目剔除时`status=not_comparable`，`score/score_lower/score_upper=null`，不生成0分、持平或胜负。

原始`assessment.summary`、逐条和逐页判断、模型原文保持不变，仍保留unknown区间。顶层`summary`使用共同剔除后的比较口径；`comparison`记录独立计分政策`exclude_unknown_across_candidates_v1`、完整候选集合、保留/剔除ID、各剔除项的触发候选、原满分、`excluded_weight`和`score_possible`。剩余条目complete不表示原始评测没有unknown或接口失败。汇总区分`assessment_complete`（原始覆盖）与`comparison_complete`（剩余条目确定）。

轻量/全量、批量judge、单例runner、离线报告及JSON/CSV/MD映射均使用此口径。离线报告重新核对共同剔除集合和分数，拒绝候选不全、不同计分政策混用或被改写的分数。发生剔除时，原有五维±20%敏感性分析标为不适用，避免隐含地把剩余维度重新分配到100分。rubric导出另含`comparison_policy`；原`scoring_policy`仍描述单份原始评分，使用者须在同题全部判断结束后执行共同剔除。

这是模型调用结束后的汇总规则，独立版本不修改冻结rubric、来源审核、提示词、rubric validator10或judge validator9，也不增加模型请求。历史报告没有`comparison`时继续按原评分和区间读取，不自动迁移或覆盖。

## 流程与状态

| 模式 | 生成后的流程 | 审核状态 |
|---|---|---|
| `light` 轻量（默认） | 提取需求 → 逐条生成问题及绑定固定库 → judge | `skipped`，未审核 |
| `full` 全量 | 提取需求 → 逐条生成问题及绑定固定库 → 初审 → 必要时最多两轮修改并重审 → judge | `passed` 或 `not_passed` |

全量在任一审核通过时结束修订。两轮修改后仍有问题，使用最后一版完整 rubric，记录 `reason=revision_limit` 及原始 `item_ids/problem/suggestion`，继续评分。固定库问题不再提前拦截，也不会通过修改来源要求伪装修复固定库；未解决问题保留在结果中。遇审核传输/格式错误，底层有界重试后记为 `audit_error`；修改生成失败记为 `revision_error`，使用上一版完整 rubric。首版生成、来源读取或结构/指纹校验失败时仍报错，不能对不存在或不完整的 rubric 评分。

执行就绪和审核批准分开：审核通过的 rubric 为 `status=approved`；轻量未审核、全量未通过的完整 rubric 为 `status=ready`。只有当前版本、来源、规范编译及哈希校验有效的产物可评分。模式与审核历史有独立指纹绑定；切换模式会保留旧产物后重建，不把轻量结果当全量审核批准复用。评分、导出及汇总继承生成时的模式，不重新选择模式，不隐藏未通过原因。`reviews.json` 保留审核历史，`rubric.json`、`status.json`、候选评分报告和汇总的 `source_audit` 同步保留状态及原因；历史报告继续按原协议读取。

## 使用方式

```bash
# 轻量生成：无需审核配置、审核Client或MaaS凭据
.venv/bin/python -m ppt_rubric contract-v2.5 generate --mode light \
  --config configs/contract-v25-k3.json --cases 02 \
  --out artifacts/new-light/rubrics

# 全量生成：显式 --mode full；首次审核后最多两轮修改
.venv/bin/python -m ppt_rubric contract-v2.5 generate --mode full \
  --config configs/contract-v25-k3.json \
  --source-audit-config configs/contract-v25-auditor.json --cases 02 \
  --out artifacts/new-full/rubrics

# 评分自动继承rubric模式；轻量和全量均使用这一入口
.venv/bin/python -m ppt_rubric contract-v2.5 judge \
  --config configs/contract-v25-judge.json --cases 02 \
  --rubrics artifacts/new-light/rubrics --out artifacts/new-light/judgments

# plan同样接受--mode，离线执行，不读取凭据
.venv/bin/python -m ppt_rubric contract-v2.5 plan --mode light \
  --config configs/contract-v25-k3.json --cases 02 --out artifacts/new-light/plan.json

# 整例runner：自动从生成走到judge；不指定--mode时为light
# 仅在当次在线运行授权范围内使用，新目录，不沿用已关闭余额
.venv/bin/python scripts/run_contract_v25_case01.py --case 02 --mode light \
  --out artifacts/new-case02-light --profile fast
```

配置也可设置 `pipeline_mode=light/full`，生成/计划命令的 `--mode` 优先。`--verification-config` 仅保留为生成/计划的来源审核配置别名；轻量模式忽略审核配置且不读取文件、不构造审核Client。`--profile fast/standard` 仍为调度参数，与轻量/全量的审核选择无关。

轻量生成逻辑调用为 **N＋1**（提取1＋逐条生成N），全量为各实际执行轮次 **Σ(N_r＋2)**（每轮另加一次审核），最多三轮。失败重试另计，N未知时不给伪造的数值上界。候选 judge 两模式完全相同，均为 **C＋P**（无视觉项时为C），内容每条看整稿，视觉每页一次评估全部5条后按条聚合。权重不因模式或审核是否通过而改变。
