# 独立人工复评模板 v2

这是未来新增复评的协议与空白模板，**不表示已经完成复评**。历史评测原文、选择、来源哈希和候选映射全部保留；新评测另存为新记录，不覆盖历史标签。

## 组织者准备

每个用例安排至少两名评测者独立完成同一任务。向评测者提供原始 prompt、附件和同一套冻结的全页渲染；隐藏模型身份、既有人工选择、其他评测者理由以及自动分数。每名评测者的候选显示顺序独立随机化，使用匿名候选代号；组织者另外保存映射及随机种子，评测者不能访问映射。

登记 PPTX 哈希、渲染 PDF/PNG 哈希、渲染器版本、字体环境、分辨率和完整页数。若另看原生 PowerPoint，作为独立的渲染版本记录；不要把两种渲染下的缺陷混作同一事实。

两人提交后先保留原始分歧，再决定是否请第三人裁决。裁决记录必须与原始判断分开，不用多数票静默替换原选择。若要测重复评测稳定性，在不展示前次结果的条件下另行随机顺序复评并记录时间；没有执行就写“未执行”。

## 评测者填写：基本信息

- 用例编号：
- 匿名评测者编号与日期：
- 评测轮次：首次独立复评 / 独立重复评测
- 看到的材料版本及渲染标识：
- 是否完整查看全部页面：是 / 否（缺页或未查看页码：）
- 是否意外看到模型身份、旧结果或他人理由：否 / 是（说明：）
- 是否遇到字体、缺图、文件打不开等环境问题：
- 阅读 prompt 后认定的任务目标、受众和明确硬要求：
- 任务未指定、属于个人偏好的部分：

先完成下面的证据记录，再填写整体选择。不要根据自己猜测的模型身份判断；不要以字多、页多、图多直接代替内容质量或可读性判断。

## 逐候选证据记录

对每个匿名候选分别复制本节。记录支持优点的证据，也记录缺陷；尚未核实的观察保留为疑点。来源没有提及的事项不等于不存在。

- 匿名候选代号：
- 完整页数：
- 最有价值的任务完成表现及对应页码：

| 记录编号 | 页码与区域 | 页面实际文字或视觉对象 | 对应 prompt/附件原文或通用质量依据 | 判断及说明 | 对任务的影响 |
|---|---|---|---|---|---|
| E01 |  |  |  | 已核实优点 / 已核实缺陷 / 待核实 / 个人偏好 | 关键任务受阻 / 局部影响 / 轻微 / 未知 |
| E02 |  |  |  |  |  |

需要时补充以下内容：

- 计算问题：原始量、单位、分母、时间起点、算式和结果；区分观测值与明确假设。
- 来源问题：具体哪一主张超出来源，哪一限定被删除；同时检查标题、图例、脚注、同页限定和已明确的全篇信息政策。
- 推理问题：前提与结论分别是什么，缺少哪个前提；“资料没给”和“推论错误”分别记录。
- 视觉问题：在指定渲染中具体哪两个对象遮挡、哪些字或图表读不清，附截图或区域；仅信息较密时不要直接记成重叠。
- 严重程度：为什么这个问题妨碍当前受众使用；同一缺陷造成多个后果只登记一个主问题，并关联后果。
- 不确定之处：需要哪些补充证据才能确认。

## 双边核对

在整体选择前，对两份作品应用相同标准。

- 同类问题在另一候选是否存在，是否采用相同的严重程度依据：
- 双方使用的是事实、建议、假设还是初步感受，是否区别对待：
- 是否把清楚标注的测算或假设当作未标注事实：
- 是否存在同一视觉/内容问题被重复计入多个理由：
- 影响判断的事实是否依赖渲染器或未核实截图：
- 自己偏好与任务明确要求发生冲突的地方：

## 整体选择（最后填写）

- 选择一个：候选 ____ 更好 / 质量相当 / 各有优缺点，难以取舍 / 证据不足，无法判断
- 选择更好或质量相当的核心理由：引用上面的证据编号，说明对任务的影响。
- 若难以取舍：哪些维度不可直接互换，怎样的使用偏好会改变选择。
- 若证据不足：缺少什么，是否为文件/渲染问题。
- 置信度：高 / 中 / 低；依据：
- 哪些新证据可能改变判断：

“质量相当”表示对该任务的实际表现相近；“各有优缺点，难以取舍”表示权衡未定；“证据不足，无法判断”表示不能可靠判断。组织者须在开始评测前规定哪些类别映射为 benchmark 的 tie，不能在看到自动分数后改变映射。

本模板不要求填写数值总分。若未来采用数值平局阈值，需先定义评分尺度和可感知差异，不能将本模板的平局直接视为任意分差阈值。

## 组织者留存与机器元数据

每名评测者原始记录独立保存，记录文件哈希、时间与匿名映射。候选规范编号由组织者转换；原始匿名选择仍保留。复评前不得将旧胜负或理由传给 rubric 生成器、judge 或其他评测模型。

当前 `import_markdown_labels` 针对每案例一份历史 Markdown；它会拒绝同案多文件。新复评使用 `python -m ppt_rubric.human_review prepare/import` 的schema-2独立目录与原始记录结构，完整保留多人判断，并由第三方显式裁决决定canonical；未裁决保持unlabeled，即使两人同意也不静默取首份。不得为了通过导入而删除其中一人的记录。静态包、哈希校验、字段与命令见[实施说明](scoring-and-human-validation-20261019.md)。

`ppt_rubric.label_reliability.analyze_label_reliability(manifest, labels, split='dev')` 可为比较报告生成结构性可靠性摘要。它不访问记录路径、不分析理由、不裁决投票、不改 canonical winner。默认仅处理开发集；留出需要显式允许。

已导入 canonical 标签可以附加以下元数据；示例仅说明字段，**不是已发生事实**：

```json
{
  "review_records": [
    {"reviewer_id": "reviewer-1", "source_path": "reviews/new/case/reviewer-1.md", "source_sha256": "..."},
    {"reviewer_id": "reviewer-2", "source_path": "reviews/new/case/reviewer-2.md", "source_sha256": "..."}
  ],
  "reliability": {
    "blindness": {"status": "blinded", "evidence": ["匿名映射由组织者单独保存及访问记录"]},
    "independent_review": {"status": "independent", "evidence": ["两份独立提交记录及提交时间"]},
    "repeat_review": {"status": "not_repeated", "evidence": ["本轮只进行首次复评"]},
    "same_render": {"status": "matched", "evidence": ["人工与模型使用同一渲染哈希清单"]},
    "tie_semantics": "仅质量相当映射为tie；难以取舍或证据不足均保留undecided"
  }
}
```

缺失的盲法、独立性、复评或渲染证据一律报告 unknown。只有状态主张而没有非空证据时，同样报告 unknown。存在证据说明不等于程序已独立验证证据属实；摘要会明确保留这一限制。
